Guide 8 of 8

Cloudflare R2 Setup.

Initial configuration for image storage: create the bucket, deploy the Worker, and verify everything works.

What this guide covers: One-time setup. If R2 is already configured, skip to the "Verifying setup" section.

Step 1: Create an R2 bucket

Step 1

Open Cloudflare Dashboard

Navigate to dash.cloudflare.com.

Step 2

Create the bucket

  1. Click R2 in the left sidebar
  2. Click Create bucket
  3. Name it neiltaylerfilm.github.io
  4. Choose your preferred region
  5. Click Create bucket

Step 2: Create a bucket policy

Step 1

Open bucket settings

Click into your new bucket, then go to Settings tab.

Step 2

Add a bucket policy

Click Add bucket policy and paste this JSON:

{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Principal": "*",
      "Action": ["s3:GetObject"],
      "Resource": "arn:aws:s3:::neiltaylerfilm.github.io/*"
    }
  ]
}

This allows anyone to view uploaded images without authentication.

Step 3: Create a Workers project

Step 1

Set up Workers

  1. In the Cloudflare dashboard, go to Workers & Pages
  2. Click Create application
  3. Choose Worker
  4. Name it neiltayler-r2-proxy (or similar)
  5. Select HTTP Handler
Step 2

Paste the Worker code

Replace the default code with:

export default {
  async fetch(request, env) {
    const url = new URL(request.url);
    
    // Handle CORS preflight
    if (request.method === 'OPTIONS') {
      return new Response(null, {
        headers: {
          'Access-Control-Allow-Origin': '*',
          'Access-Control-Allow-Methods': 'GET, OPTIONS',
        }
      });
    }

    // Only allow GET requests
    if (request.method !== 'GET' && request.method !== 'OPTIONS') {
      return new Response('Method not allowed', { status: 405 });
    }

    // Read the path and construct the R2 URL
    const r2Key = url.pathname.slice(1); // Remove leading slash
    
    if (!r2Key) {
      return new Response('No path provided', { status: 400 });
    }

    // Fetch from R2
    const r2Url = `https://pub-${env.R2_ACCOUNT_ID}.r2.dev/${r2Key}`;
    
    try {
      const response = await fetch(r2Url);
      
      if (!response.ok) {
        return new Response('File not found', { status: 404 });
      }

      // Return the image with proper CORS headers
      const headers = new Headers(response.headers);
      headers.set('Access-Control-Allow-Origin', '*');
      
      return new Response(response.body, {
        status: response.status,
        statusText: response.statusText,
        headers
      });
    } catch (error) {
      return new Response('Error fetching file', { status: 500 });
    }
  }
};
Step 3

Bind the R2 bucket

  1. In the Worker configuration, find Variables
  2. Click Add binding → R2 Bucket
  3. Name: r2 (this is what the code references as env.r2)
  4. Select your bucket: neiltaylerfilm.github.io
Step 4

Deploy the Worker

Click Deploy. The Worker will now be available at:

https://your-worker.your-subdomain.workers.dev/

Step 4: Update the images registry

The website uses a local JSON file to track uploaded images. After deploying the Worker, update src/data/r2-images.json with the Worker URL pattern.

{
  "baseUrl": "https://your-worker.workers.dev/",
  "images": []
}

Verifying setup

  • Upload a test image to the R2 bucket via the dashboard
  • Try accessing it via the Worker URL
  • The image should load in your browser
  • Check that the Access-Control-Allow-Origin header is present

If the Worker returns 404: Check that the bucket name in the Worker matches your actual bucket name exactly.
